# Инструкции для AI Агентов (Авторынок Аналитика)

Добро пожаловать в проект аналитической платформы автомобильного рынка Казахстана!
Этот файл содержит ключевые директивы для ИИ-разработчиков, агентов и ассистентов, работающих с этой кодовой базой.

## 1. Технологический стек проекта
- **Инфраструктура:** Docker, Docker Compose (раздельная контейнеризация каждого сервиса).
- **Оркестрация парсинга:** Apache Airflow, Python (BeautifulSoup, Scrapy, Playwright).
- **База Данных:** PostgreSQL, Redis (для кэша).
- **Backend API:** FastAPI (Python) или NestJS/Node.js (уточняется у пользователя).
- **Frontend Dashboard:** Next.js / React (Mobile-first подход).

## 2. Архитектурные Принципы
1. **Строгая изоляция:** Ни один сервис не должен зависеть от файловой системы другого сервиса. Все общение между парсерами, БД, Бэком и Фронтом происходит строго через сеть (API, TCP порты).
2. **Отказоустойчивость инфраструктуры:** Все `docker-compose` сервисы должны иметь `restart: unless-stopped` (или `always`), а также прописанные `healthcheck`.
3. **Единая база истины:** PostgreSQL хранит все данные. Изображения не сохраняем (чтобы не раздувать хранилище), сохраняем только ссылки или вовсе игнорируем их, если они не нужны для аналитики.

## 3. Разработка Парсеров (CRITICAL)
- **Умный обход блокировок:** Сайты вроде *kolesa.kz*, *olx.kz* активно борются с парсингом. ВСЕ HTTP-запросы в парсерах должны быть готовы к ротации Proxy и User-Agent.
- **Обработка ошибок:** Ошибки 403, 429 или таймауты не должны крашить процесс парсинга глобально. Используй библиотеки с поддержкой `Retry` (например, requests-retry, tenacity или встроенные механизмы Airflow).
- **Никакой перегрузки:** Обязательно внедрять задержки (sleep) между запросами, чтобы не DoS-ить целевые сайты.

## 4. Разработка Frontend (CRITICAL)
- **Mobile-First Дизайн:** Разработка начинается с мобильных экранов. Все фильтры, графики (Chart.js / Recharts / ECharts) и таблицы должны быть читаемы и удобны на смартфонах.
- **Премиальный визуал:** Используем современные дизайн-паттерны (стекломорфизм, сочные и нескучные цвета для графиков, скелетоны во время загрузки, плавные транзиции). 

## 5. Процесс работы ИИ-агента
- При получении задачи всегда сначала проверяй проект и архитектуру в `implementation_plan.md` (в артефактах).
- Автоматизируй все, что можно автоматизировать (Airflow, Docker, CI/CD).
- Всегда используй абсолютные пути при редактировании файлов.
- Создавай красивый и понятный код, с комментариями и типизацией.
- Не запускай `cat` или `grep` в терминале напрямую, используй предоставленные тебе инструменты (view_file, grep_search).
